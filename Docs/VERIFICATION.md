# Проверки и границы готовности

## Что действительно проверено при подготовке

- Архив распакован; версия проекта — Unity 6000.0.68f1.
- Прочитано ТЗ, просмотрены исходные реализации и соответствующие разделы лекций.
- Доступны FBX модели Sorceress, текстура и семь используемых FBX анимаций: Idle, WalkForward, Run, Attack1, RangeAttack1, LightHit, Death.
- Новые C# файлы проходят синтаксический разбор Tree-sitter C# без ERROR/missing nodes. Это не заменяет компиляцию со сборками Unity.
- JSON файлов `.asmdef` корректен; новым файлам и папкам назначены `.meta`, конфликтов GUID нет.
- Все исходные файлы присланного ZIP побайтно сохранены. Добавлен отдельный модуль и документация.

**Unity Editor, компиляция C# со сборками Unity, EditMode/PlayMode тесты и Windows-билд здесь не запускались.** Сцена, controller и копии клипов создаются редакторской командой на компьютере с Unity. Переходы анимаций, Humanoid-retargeting, положение меча в руке и внешний вид интерфейса не проверены визуально. Исходные `.meta` модели Sorceress содержат старое предупреждение о различиях длин костей; его влияние нужно оценить в Unity. Оно не было замаскировано изменением исходных метаданных.

## Тесты внутри проекта

После команды Build playable scene:

1. Выполните `Tools → Lab 1-2 → Validate generated assets`. Проверяются ссылки, меши, Avatar доступной модели, отсутствие старых скриптов/событий в визуальных префабах, времена ударов. Для импортированных исходных монстров — ожидаемые параметры Animator.
2. Откройте `Window → General → Test Runner`.
3. Запустите EditMode, затем PlayMode. Запускайте тесты вне ручного Play Mode.

| Набор | Сценарии |
|---|---|
| DomainTests | Начальное HP; недопустимые значения; события урона; однократная смерть; нулевой урон; однократный удар; длинный кадр; прерывание; запрет очереди; новая атака после отмены; границы дистанций AI и отсутствие видимости |
| CombatPhysicsTests | Несколько коллайдеров цели дают один удар; союзник и цель за спиной не получают урон; стена блокирует удар; фильтрация союзного урона |
| ProjectileTests | Быстрый снаряд попадает один раз; стена останавливает его перед целью; попадание при начальном пересечении |

Тесты добавлены, но их результат станет известен после запуска в Unity. Сообщение `asset validation passed` не означает, что автоматически проверен геймплей.

## Анимации: что подстраивается визуально

Сборщик задаёт разумные стартовые значения; особенно проверьте:

- Совпадает ли момент уменьшения HP с замахом/контактом меча. Меняйте `Melee Impact`, а не код здоровья.
- Совпадает ли вылет снаряда с жестом руки. Меняйте `Magic Impact`.
- Не слишком ли длинна блокировка при `Hit`. Начальное значение — 0,35 с; LightHit ускоряется под эту длительность параметром ActionSpeed.
- Меч прикреплён к `B_R_Hand`. Если его положение не совпадает с хватом, откройте `HeroVisual.prefab` и отрегулируйте локальный поворот/позицию объекта `Sword`. Проверить хват в среде без Unity невозможно.
- После возврата исходных монстров времена от Sorceress не обязаны совпадать с их клипами. Их надо настроить в `MeleeEnemy.asset` / `RangedEnemy.asset`.

## Если что-то не открывается

- Нет пункта Tools → Lab 1-2: сначала проверьте красные ошибки Console и завершение импорта пакетов. Новые редакторские скрипты должны скомпилироваться, прежде чем появится меню.
- Открылась старая игра: запущена SampleScene. Нужна Generated/Lab12.unity после сборки.
- Не восстановился монстр: нужны оригинальные `.meta`, меши и controller из удалённой папки; простое совпадение имени файла не восстанавливает GUID.
- Материал розовый: проверьте импорт URP и наличие шейдера Universal Render Pipeline/Lit. Новые материалы создаются под URP; исходные материалы ассета остаются нетронутыми.
- Изменили карту и враги не появляются: проверьте коллайдеры, слой LabWorld и принадлежность объекту World. Спавнер пишет ошибку, если не нашёл достижимую свободную точку.
