# RPG: практические работы 1–4, лабораторные 1–2

Переработанная реализация первого раздела ТЗ: персонаж, HP и два типа урона, два типа врагов, локация, интерфейс и инверсия зависимостей. Главное меню, сохранения, боссы и другие задания следующих лабораторных не добавлены.

**Unity: 6000.0.68f1**, как в присланном проекте. Версии пакетов сохранены.

## Запуск

1. Распакуйте архив в отдельную папку и откройте её через Unity Hub. Дождитесь импорта ассетов и пакетов.
2. В верхнем меню Unity выберите **Tools → Lab 1-2 → Build playable scene**.
3. Будет создана и открыта сцена `Assets/Lab12/Generated/Lab12.unity`. Нажмите **Play**.
4. Щёлкните по окну Game, если мышь ещё не захвачена.

Команда создаёт сцену, префабы визуальных моделей, материалы URP, настройки персонажей, копии клипов и простой Animator Controller. NavMesh строится при запуске до спавна персонажей. Новая сцена ставится первой в списке сборки, чтобы работал Restart. Команду не нужно выполнять при каждом запуске: после первой сборки открывайте `Lab12.unity`.

**В архиве лежит исходный код сборщика; `Generated` появится после выполнения команды в Unity.** Unity Editor в среде подготовки отсутствует. Здесь выполнены проверка синтаксиса C#, структуры сборок, GUID и сохранности исходных файлов; компиляция Unity, тесты Unity и визуальная проверка не выполнялись. Это не архив проверенного Windows-билда.

Если у вас уже открыт полный рабочий проект с `Resources`, можно скопировать в него только новую папку `Assets/Lab12` вместе с её `.meta`, затем выполнить Build playable scene и Import original monster visuals. Старые папки заменять не требуется.

## Управление

| Клавиши | Действие |
|---|---|
| WASD / стрелки | Движение относительно направления камеры |
| Shift | Бег |
| Мышь | Поворот камеры |
| ЛКМ | Удар мечом в направлении камеры по горизонтали |
| ПКМ | Магический снаряд в направлении камеры по горизонтали |
| Esc | Освободить курсор; игра продолжает идти |
| ЛКМ после освобождения курсора | Захватить курсор; этот клик не выполняет атаку |
| Restart после смерти | Перезапустить сцену |

Один клик запускает одну атаку. Удержание кнопки не создаёт очередь ударов. Во время атаки или реакции на урон передвижение блокируется. Снаряд летит горизонтально на уровне корпуса; вертикальное положение камеры не задаёт угол выстрела. Центральный маркер помогает ориентироваться по направлению.

## Папка Resources и монстры

Удалённая папка не восстановлена из воздуха. Исходные префабы `Assets/Prefabs/Meele.prefab` и `Range.prefab` сохранены с их ссылками. Старый `Player.prefab` тоже имеет отсутствующие внешние ресурсы, поэтому новый герой использует имеющуюся модель Sorceress.

Для запуска без тяжёлой папки новая сцена использует три варианта доступной Sorceress: герой, красноватый враг ближнего боя с мечом и фиолетовый враг дальнего боя. Поведение и HP у врагов разные; все варианты анимированы имеющимися клипами. Это временная замена внешности монстров, а не восстановленные исходные модели.

Чтобы вернуть своих монстров:

1. Скопируйте оригинальную папку `Resources` **на прежнее место внутри Assets**, вместе со всеми `.meta`. Если она была вложена в другую папку, сохраните тот же путь.
2. Дождитесь импорта Unity. Сначала один раз соберите новую сцену командой выше.
3. Выполните **Tools → Lab 1-2 → Import original monster visuals**.
4. Затем выполните **Tools → Lab 1-2 → Validate generated assets**.

Импортёр создаёт отдельные визуальные префабы: оставляет модели, скелеты, Animator и материалы, убирает старые компоненты управления/AI/урона, копирует клипы без событий старого кода. Исходные префабы не изменяются. Если меш или контроллер не восстановлен, импорт данного монстра прекращается, а доступная модель остаётся в настройках.

Адаптер исходных монстров рассчитан на параметры, использованные вашим прежним кодом: `Walking` (bool), `Attack`, `TakeDamage`, `Death` (trigger). Валидатор проверяет эти параметры. Контроллеры из отсутствующей папки здесь нельзя было изучить и проверить в движке. После импорта сравните длительность атак, момент попадания, реакцию и смерть с их клипами и поправьте соответствующие поля настроек. Инструкция ниже объясняет, где это делать.

## Где менять параметры

После сборки откройте `Assets/Lab12/Generated`:

- `Player.asset`: HP, физический и магический урон, ходьба/бег, время ударов и кулдауны героя.
- `MeleeEnemy.asset`, `RangedEnemy.asset`: аналогичные параметры врагов.
- `Character.controller`: новый Animator для доступной Sorceress.
- `Clips`: отдельные копии семи используемых анимаций.
- `HeroVisual.prefab`, `MeleeVisual.prefab`, `RangedVisual.prefab`: внешний вид доступных персонажей.

`Melee Impact` и `Magic Impact` — секунды от начала атаки до попадания/вылета снаряда. `Duration` — время блокировки атаки и возврата в перемещение. Первоначально длительность берётся из соответствующего клипа, момент удара — 38% его длины, выстрела — 35%. Эти точки требуют визуальной подстройки под конкретный клип. `Hit Duration` задаёт длительность реакции (по умолчанию 0,35 с, клип ускоряется через `ActionSpeed`), `Death Duration` — задержку удаления врага. Кулдаун считается от старта атаки и не сбрасывается при прерывании.

Повторная сборка **пересоздаёт нашу сцену**, но сохраняет существующие настройки и сгенерированные ассеты, чтобы не затереть вашу настройку параметров и анимаций. Перед повторной сборкой сохраните отдельно ручные изменения локации. Для полной генерации заново можно удалить только `Assets/Lab12/Generated` и повторить команду.

## Что читать в коде

Вся новая реализация: `Assets/Lab12`. Исходные `Assets/Scripts`, `Assets/Prefabs`, `SampleScene` и папки ассетов сохранены без изменений как исходная версия. На новой сцене старые контроллеры не создаются и не управляют персонажами. Не проверяйте новый код в старой `SampleScene`.

Начните с `SceneBootstrapper`, затем `ActorFactory`, `Health`, `ActorCombat`, `AttackTimeline` и `CharacterAnimation`.
